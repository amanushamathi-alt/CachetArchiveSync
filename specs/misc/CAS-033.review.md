# Review Report — CAS-033 (Index Refresh Scripts Store the Full B2 Key in `relative_path`)

> Scope note: this reviews `specs/misc/CAS-033-index-refresh-full-key-paths.md` only. The unrelated
> `specs/web/cachet-archive-sync/CAS-033-task-manager-modal-reachability.md` (duplicate ID) was not reviewed.

## Verdict: BLOCKED

> **BLOCKED** — Security violation or significant scope violation. Do not merge.

**Why BLOCKED:** `scripts/index_refresh/requirements.txt`, in the folder this change delivers and the file the
README tells operators to install from (README.md:55), contains a **plaintext B2 bucket name, application key ID
and application key** (lines 4-6). That is a direct B2 credential exposure (FR-03, CLAUDE.md rule "the B2
application key ... must never appear in a commit"). Its mtime (2026-09-30 14:34) predates the CAS-033 edits
(2026-10-01 11:11-11:15) and it is not in §5, so it was most likely **not introduced by CAS-033**. It still blocks
release of this folder, and it also breaks README step 3, because `pip install -r requirements.txt` cannot parse
those lines.

**The CAS-033 code on its own** would rate **APPROVED WITH NOTES**. The script logic matches §2. All 10 unit tests
pass. The guards are correct and ordered before any change. Nothing CAS-033-related was found under `src/`,
`Database/` or `docs/`. One blast-radius item §4 missed is recorded in §10 (`B2MirrorSyncTaskProcessor`).

### Unintended Side Effects
- **`B2MirrorSyncTaskProcessor` (CAS-037), which §4 did not list.** It is reachable through
  `POST /sync/mirror-sync` (SyncController.cs:133-135, `CachetAuthenticated`). It enumerates the **whole bucket**
  (B2MirrorSyncTaskProcessor.cs:74-83), stores `b2File.FileName` (the full key) as `relative_path` (:105),
  downloads to `b2_mirror_root_path + key` (:125) and upserts `source='B2'` rows.
  - Its key scheme now matches CAS-033. But under the new mapping (`b2_mirror_root_path = D:\Cachet-Server-C`) it
    would index and download objects **outside the prefix**: the §13 decoys `finance/a.xlsx` and
    `D/Shares/Operations2/...`.
  - Consequences:
    - (a) The next `refresh_b2_index.py` run aborts on the stale-catalog guard, which is safe but blocking.
    - (b) Content Scan could list those out-of-prefix rows as B2-only. That would make bucket-root decoys
      candidates for **Purge**, an irreversible action, which is exactly the outcome the decoys in E3 are meant
      to catch.
    - (c) Keyword Search could confirm the root-level decoy, which contradicts E6.
  - This is pre-existing app behavior and outside CAS-033's file scope, so it is not a defect in this diff. It is
    a blast-radius omission with a direct effect on SC-5/SC-7 and on the safety of the irreversible actions.

## 10. Reviewer Notes

1. **B2MirrorSync interaction (see §6).** Before E3/E6 and before any production use, do one of the following:
   - (a) operationally forbid `POST /sync/mirror-sync` while CAS-033 data is in use; or
   - (b) raise a follow-up change spec to scope B2MirrorSync to `b2_path_prefix`; or
   - (c) at minimum, add it to §4 Known Effects and to the README.

   Also run E3 and E6 with a B2MirrorSync run included to confirm the decoys stay untouched.
2. **Spec §7.2 FK order is wrong.** The README is correct (see §5). Update the spec text.
3. **Spec §1 line references have drifted.** For example, the cross-check is now KeywordSearchTaskProcessor.cs:316.
   This is informational only; the hand-off note allows for it.
4. **Empty prefix disables the guard (V5).** If the prefix is ever changed to empty on a catalog holding full
   keys, the guard will not fire, and the mass-delete guard is the only remaining protection. The README's "reset
   whenever the prefix changes" covers this procedurally.
5. **Cosmetic.** If the scan root itself cannot be read, the report row key becomes `D/Shares/Operations/.`
   (odrive:43, `relative_to` gives `.`). This affects the report only, not the database.
6. **Audit detail `prefix` field** (b2:260). This is configuration text, not a file path. Confirm it is acceptable
   under the "counts only" rule.
7. Status in the frontmatter is `review`. Leave it there until the blocking item is cleared and the manual E2E (§13)
   has run.
