### Unintended Side Effects

1. **WebApplicationFactory hosts now call the DB at startup.** `Api.IntegrationTests/*WebApplicationFactory.cs`, `Web.Tests/Auth/LoginWebApplicationFactory.cs` and `Web.Tests/TaskPollingOptionsTests.cs` all start the real `Program`. The factory's `ConfigureAppConfiguration` runs only at `Build()`, so the DB source is created from whatever `ConnectionStrings__CachetArchiveSync` environment variable the test process inherits. If that variable points at a database without `dbo.configuration_detail_lst`, or at an unreachable server, these factories now fail to start with the V3 exception. Before this change they did not touch the DB. Test overrides still win, because they are added after the DB source. In this run the Web.Tests factory tests passed, because the variable is set in this environment. Recommendation (non-blocking): have the factories set `ConfigurationDatabase__Enabled=false` in their constructors, following the precedent in `UsersAdminApiWebApplicationFactory.cs:59-61`.
2. **Dev override of `Api:BaseUrl`.** `Web/appsettings.Development.json:17` sets `Api:BaseUrl = https://localhost:7244/`. On a developer machine, an `Api_Url` row in the shared dev DB now overrides that. This is the precedence the spec intends, but a developer running Api locally could be sent to the server's Api. It belongs in the dev notes.

## 10. Reviewer Notes

1. **DB-layer least privilege for Web (non-blocking).** Web's allow-list keeps the system key out of `IConfiguration`, but Web's DB login can still read it through the SP, and the full `B2_Keys` rows pass through Web's memory. Options, ordered by effort:
   - (a) The §11 compensating control, plus a separate Web DB login without EXECUTE on this SP. This needs a separate grant path.
   - (b) An SP variant, or an optional `@ConfigurationDetailName` filter, so Web requests only `B2__BucketName`.
   - (c) Accept as is. The client already accepted plain-text storage.
2. **WebApplicationFactory startup now depends on the DB**; see §6 side effect 1. Recommend `ConfigurationDatabase__Enabled=false` in the test factories.
3. **Allow-list duplication.** The SC-4 test restates Web's allow-list (`DatabaseConfigurationProviderTests.cs:21-25`). A later edit to `Web/Program.cs:24-28` would not be caught. Low risk, since today they are identical.
4. **Stale §1 line references** after the CAS-040 edits: `KeywordSearchService.cs:204→206`, `KeywordSearch.razor:709→728`, `Web/Program.cs:140→157`. Cosmetic.
5. **Web.Tests failures** (`ODriveSyncPageTests` SC10 and V9 `actionPoll`) fail every time and come from the CAS-040 changes to `ODriveSyncContentScan.razor`. Track them under CAS-040.
6. **§16 manual verification** (three hosts started against the dev DB with the four environment variables unset) was not run by the reviewer. It should be done and recorded before the spec status moves to `done`.
7. **Operational:** rotate the B2 system key that was exposed in the screenshot (§11).
8. The §14 open questions still stand: there is no unique index on (`Configuration_id`, `configuration_detail_name`), and with duplicate rows the last one wins, which matches `Data[key] =` at `:79`.
