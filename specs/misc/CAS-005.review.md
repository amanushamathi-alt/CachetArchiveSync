## 10. Reviewer Notes

- Worker -> Api `ProjectReference`: flagged above (Section 6) as consistent with the clean-architecture
  skill's prose but a deviation from its diagram. This means `Cachet.ArchiveSync.Worker` now
  transitively depends on the entire ASP.NET Core Web API assembly (controllers, Program.cs
  top-level host, all of Api's other dependencies) just to reuse two concrete classes. The skill
  itself anticipates this being revisited ("via a shared Infrastructure project if the pattern
  repeats") - recommend the team treat this as a tracked follow-up: extract `AuditLogRepository`/
  `AuditLogService` (and any future Worker/Api-shared infrastructure) into a dedicated
  `Cachet.ArchiveSync.Infrastructure` project the next time a second implementation-sharing need
  arises, per the skill's own stated trigger condition.
- SC-1/SC-2 DB-unavailable skip is honestly and clearly documented in three independent places
  (spec Implementation Log, test class doc comment, `Skip` reason string) - this is the kind of
  disclosure the review criteria treat as PARTIAL rather than FAIL. Re-run these two tests against
  a real SQL Server instance before considering CAS-005 fully closed; this is a pre-merge action
  item, not a blocking defect in the code itself.
- Section 15's two open questions (enum naming convention; `created_by`/`updated_by` identity value) were
  both resolved with rationale prior to implementation and are reflected correctly in code
  (`AuditAction.cs`/`AuditResult.cs` doc comments cite Section 15; `AuditLogEntry.cs` doc comments on
  `CreatedBy`/`UpdatedBy` cite the "api-svc"/"worker-svc" convention) - not silently defaulted.
- V1's tab_module check uses `StringComparer.Ordinal` (case-sensitive, exact match) - correctly
  rejects the `"auth"` (lowercase) test case, matching the SQL `CHECK` constraint's exact-string
  semantics.
