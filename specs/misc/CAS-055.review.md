## 10. Reviewer Notes

- **N1 (low; SQL robustness):** the helper rejects `@watermark <= 0` via `RAISERROR`. The sweep calls it for any non-NULL watermark. If a watermark of 0 were ever persisted, the RAISERROR inside the caller's TRY would roll back the whole sweep, and the Worker's retry loop would spin forever with no claims. Persisting 0 appears unreachable (`file_index_id` is an IDENTITY, positive), so this is a theoretical wedge risk. It is worth hardening by adding `resume_watermark_file_index_id > 0` to the eligibility predicate. A bad row must never block service start.
- **N2 (low):** unused `DECLARE @err NVARCHAR(MAX) = ERROR_MESSAGE();` in the sweep CATCH block (dead code).
- **N3 (medium design observation, not a spec violation):** the superseded original stays `Failed` and (per the existing Task Manager rules) restartable. A user clicking Restart on an auto-resumed original would create a second concurrent lineage for the same search, with `auto_resume_count` reset to 0. The spec does not forbid it, and SC-5 requires manual restart of the *suppressed* row. Consider a follow-up to block or warn on restarting a row that already has a child (`restarted_from_task_queue_id` pointing at it).
- **N4 (low):** `Test_CAS055_Sweep_LogsOneWarning...` asserts presence but not "exactly one" per id. Tighten with `ReceivedLogContaining` counts.
- **N5 (low):** `WorkerOptionsTests` was not extended for the new options.
- **N6 (info):** Filename-mode keyword searches never write a watermark (CAS-054), so they are never auto-resumed. This is consistent with §2.2 and the "behave as today" rule.
- **N7 (info):** compliance gate. Spec §14 Q1 (BRD amendment for the user-initiated restart model) remains open and external. Do not describe auto-resume to auditors as approved behavior until the client accepts it. `Worker:AutoResumeMaxAttempts = 0` is the kill switch.
- Prior CAS-054 defect probe (`Test_DefectProbe_WatermarkAdvancesPastDroppedContentCandidates`): the processor now routes dropped Content candidates through `CompleteCandidateAsync` (`KeywordSearchTaskProcessor.cs` lines 236, 253, 348), so the watermark advances. This matters because auto-resume is only reachable for rows with a watermark.
