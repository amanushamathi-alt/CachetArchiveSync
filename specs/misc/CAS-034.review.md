## 10. Reviewer Notes

- **Coverage figure not independently re-derived.** The Implementation Log's 85.9% coverage claim on changed lines could not be independently reproduced in this review pass — a coverlet `/p:CollectCoverage=true` invocation against the test project produced no coverage artifact in this environment (likely missing package wiring at the csproj level, not investigated further since re-deriving exact coverage is outside a correctness review's critical path). The underlying claim is plausible given the breadth of new tests (22 new methods spanning all 8 `IB2Client` operations, including dedicated retry-path tests for 5 of the 6 wrapped operations) but is recorded here as **implementer-reported, not reviewer-verified**.
- **`GetBucketIdAsync` exclusion is spec-consistent, and this reviewer independently confirms and agrees with that characterization** (Phase 8 requirement). `GetBucketIdAsync` (`B2Client.cs:150-187`) calls `SendWithReauthAsync` directly, never `SendWithRetryAsync` — it is not one of the six/seven named retry-eligible operations, exactly as §2 and §14 state. One second-order consequence worth flagging for awareness (not a defect, since it follows directly from the spec's own explicit scoping, already logged as an open question in §14): `ListFileNamesAsync`, `ListFileVersionsAsync`, and `GetUploadUrlAsync` each call `GetBucketIdAsync` *before* entering their own `SendWithRetryAsync`-wrapped wire call (e.g. `B2Client.cs:392-403`). On a cold cache (`_cachedBucketId is null`), a single transient `b2_list_buckets` blip will still fail these three operations immediately and unretried, even though the operation's own named wire call is fully retry-wrapped. This narrows the practical resilience benefit for these three operations specifically on a cold-cache path, until the bucket id is cached for the process lifetime (after which this code path is never hit again). Recommend the team explicitly re-confirm at the next opportunity (per §14's own open item) whether this narrow gap is acceptable or warrants a follow-up spec.
- **Stale graph edge** — see §6 above (`QuarantinePermanentDeleteService` no longer depends on `IB2Client`). Recommend a `graphify update .` run (per this project's CLAUDE.md rule "After any implementation, run `graphify update .` to refresh the graph") on the Windows host, since this review's sandbox access is read-only per its mandate.
- Implementation Log's self-reported Gate 2 characterization of `Worker.Tests`/`Web.Tests` failures as pre-existing and unrelated was independently spot-checked for `Worker.Tests`: re-ran `WorkerTaskModuleMapTests` and confirmed all 6 failures are the identical `FileNotFoundException` for the missing `dbo.task_queue_sweep_interrupted.sql`, unrelated to any CAS-034 file. `Web.Tests` was not independently re-run (bUnit UI-timing flakiness, plausible on its face and does not touch B2Client — not on this spec's critical path).
