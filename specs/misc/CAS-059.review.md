## 10. Reviewer Notes

### Focus area (a): `IsLocalCopyCurrentAsync` (V3 amended)

**What is correct:**
- **Time comparison:** `FileInfo.LastWriteTimeUtc` and `DateTimeOffset.FromUnixTimeMilliseconds(..).UtcDateTime` are both UTC. `DateTime ==` compares ticks only, so `DateTimeKind` and daylight saving cannot affect it. NTFS stores 100 ns ticks, and a millisecond value round-trips exactly, including over SMB to an NTFS-backed share. SC-18 verifies the round-trip on local NTFS.
- **Order of checks:** the hash runs only after the index SHA-1 matches and the size matches (P:162-165, P:395). The hash cost is therefore limited to objects that would otherwise be skipped.
- **Copy/Update interaction:**
  - `SyncCopyTaskProcessor` (`:99-122`) and `SyncUpdateTaskProcessor` (`:102-106`) write the SHA-1 and size to the index but never write a mirror file.
  - A Copy leaves no file, so SC-1 applies.
  - An Update leaves the old content with the old upload time, which differs from the new upload time. The hash then differs and the file is downloaded (SC-17).
- **Adopting the upload time never marks wrong content as current:** the time is set only after the content hashes to the B2 SHA-1 (P:418-425).
- **Remaining trust point:** the cheap time path trusts any same-size file whose time is exactly the upload time. Only Mirror Sync's own verified download sets that time.
- **Exception paths:**
  - All errors are raised inside the per-object `try` (P:154-206), so a locked file or access denied while hashing fails that object only.
  - `FileInfo.Exists` returns false on access denied. That leads to a download, which then fails at `File.Move` and counts as failed.
  - Cancellation (`HashDataAsync(stream, ct)`) passes through both catches, which is the existing contract.

**Notes:**
- **N1 (low; the spec claim is overstated):** the hash path does not cover script-placed files when the B2 SHA-1 is `none` or `unverified:<hex>`.
  - For those objects `refresh_b2_index.py` stores the local hex hash or `large_file_sha1` in `file_index.sha1_hash` (`refresh_b2_index.py:61-62, 180-182, 216-222`).
  - Mirror Sync compares the index value with the raw `contentSha1` (P:164). The values never match, so the file is downloaded again.
  - Mirror Sync then stores the raw `contentSha1` value. The next `--apply` run of the script writes the hex hash back.
  - Result: large or `unverified` files are re-downloaded after every script run. Data stays correct, but bandwidth is wasted.
  - Suggestion: normalise the SHA-1 format the two tools store, as a separate spec.
- **N2 (low; the cost is understated):** spec §2 says "the first run after deployment hashes each script-placed mirror file once".
  - Every SHA-matching file whose time is not the upload time is also hashed once. That likely includes files written by the pre-CAS-059 Mirror Sync (`FileMode.Create`, time = download time). This cannot be verified because there is no history.
  - The first run may therefore read most of the sync folder over SMB. Plan the first run outside busy hours.
- **N3 (low; depends on the environment and unverifiable here):** exact time equality needs a filesystem that stores at least millisecond precision.
  - If `\\svsws10\B2mirror` is on NTFS, this works.
  - On FAT/exFAT or a NAS that rounds times, the cheap path never matches. Every run would re-hash every SHA-matching file. Results stay correct; only performance suffers.
  - Confirm the share's filesystem during §16 verification ("a second run skips them"), and check the run duration.
- **N4 (minor):** when `SetLastWriteTimeUtc` fails while adopting the time (P:427-430), the error is swallowed without a log line. The file is then re-hashed on every run without any visible sign. A debug or warning log would make this observable.
- **N5 (minor):** in `DownloadVerifiedAsync`, if `SetLastWriteTimeUtc` (P:301) throws after `File.Move` succeeded:
  - the object is counted as failed and its row is not updated;
  - the mirror file already holds the correct content.
  
  The next run repairs this through the hash path or a re-download. It is harmless but slightly misleading in `FailedCount`.

### Focus area (b): `ResolveInsideRoot` (P:437-449)

`GetFullPath` does no disk I/O, so the tests run on any Windows host whether or not `E:` exists.

| Root | `TrimEndingDirectorySeparator` | `EndsInDirectorySeparator` | Prefix used | Result |
|------|------|------|------|------|
| `E:\` | `E:\` (a root is not trimmed) | true | `E:\` | Correct. This was the old double-separator bug |
| `E:\x` | `E:\x` | false | `E:\x\` | Correct |
| `E:\x\` | `E:\x` | false | `E:\x\` | Correct |
| `\\svsws10\B2mirror` | unchanged (`GetPathRoot` of a UNC path has no trailing separator) | false | `\\svsws10\B2mirror\` | Correct |
| `\\svsws10\B2mirror\` | trimmed to `\\svsws10\B2mirror` | false | `\\svsws10\B2mirror\` | Correct |

- The sibling test (`E:\B2mirror` with `../B2mirror-other/x.txt`) would pass under the old code only if the separator were missing. It is therefore a real regression test for the prefix-without-separator mistake.
- All 5 theory cases and the sibling fact pass.
- A drive root cannot be escaped: `GetFullPath` clamps `..` at the root.

### Focus area (c): name filters and log sanitising

- `IsExcludedName` (P:330-338) is equivalent to `fnmatch` on `common.py:40`, ignoring case as on Windows.
- `InvalidPathReason` (P:342-374) mirrors `validate_relative_path` (`common.py:193-212`), plus the `\` rule. Its limits match: 1000 characters, 1024 UTF-8 bytes, 500 for the file name, 10 for the extension.
- `ForLog` (P:376-383) replaces every `char.IsControl` character in the skip warning.
- **N6 (minor):** the per-object failure warning (P:203-205) logs the raw `relativePath`.
  - Names containing DEL, C1 controls (e.g. U+0085 NEL) or U+2028/2029 pass V12 (which blocks only characters below 32) and could reach that log line.
  - CR/LF cannot, so SC-16 holds as written.
  - Suggestion: use `ForLog(relativePath)` there too.
- **N7 (low; the script has the same gap):** V12 does not reject segments ending in `.` or a space, or Windows reserved device names (`CON`, `NUL`, ...).
  - `GetFullPath` strips trailing dots and spaces, so `a/x.txt` and `a/x.txt.` resolve to the same mirror file. This is the same collision class that the `\` rule closed.
  - The two objects would overwrite each other on alternate runs. Each run downloads and re-verifies, so the mirror never keeps content that fails verification, but the File Viewer could show the other object's bytes between runs.
  - Consider a follow-up that rejects trailing `.` or space in segments in both Mirror Sync and `common.py`.
