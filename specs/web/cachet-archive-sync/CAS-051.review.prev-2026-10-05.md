### D-1 trace (prefix) — RESOLVED

- The Web sends the root-relative `folder.Path` taken from the browse response (`FileExplorer.razor:190`, `:965`, `:773`; `listing.Folder` for state), `Source="B2"`, and `BucketName` from `B2:BucketName`.
- Controller: `QuarantineController.cs:72`, `:106`, `:136`. These call the service.
- `QuarantineBrowseService.ResolveFullPathAsync` (`:241-265`) handles B2:
  - It calls `IB2PathPrefixProvider.GetPrefixAsync(request bucket)`.
  - A null prefix returns `MappingMissing` without any repository or audit call (fail closed).
  - Otherwise it builds `fullPath` with `B2KeyPath.Combine(prefix, folder)`. An empty folder returns the prefix; otherwise `prefix/folder`.
  - A length above `FileBrowseService.MaxFolderLength` returns `TooLong`, which becomes a 422 validation failure.
- It is applied to all three routes:
  - add at `:92-104`
  - remove at `:157-169`
  - state at `:208-219`
- The audit row for folder add and remove carries the full key path (`:111`, `:176`). File scope audits `file.RelativePath`, as before.
- The state SP (`dbo.quarantine_entry_browse_state_lst.sql`) matches `file_index.relative_path` by `fullPath + '/'` and returns leaf `folder_name` values, which the Web keys on `folder.Name`. This is consistent.
- `MappingMissing` returns HTTP 500 `mirror-mapping-missing` through `BrowseMappingMissingProblem` (`QuarantineController.cs:93`, `:119`, `:150`). The Web's `SendAsync` maps any 5xx to `Failed`. The result is the generic "The quarantine action could not be completed. Try again." For a state load, the checkbox column is hidden with the same generic message (`:800-802`, test `Test_StateLoadFailure_HidesColumnWithGenericMessage`). No ProblemDetails text reaches the UI.
- Api coverage with a non-empty prefix:
  - `Api.Tests` `QuarantineBrowse*` pass (57 tests).
  - `Api.IntegrationTests/QuarantineControllerTests.cs:502`, `:578`, `:605`, `:647`, `:669` assert `D/Shares/Operations/Ops…`.
  - `QuarantineBrowseRepositoryTests.Test_SC7_EndToEnd_PrefixedBucket` (:656) runs the real service and SPs with `D/Shares/Operations`. It substitutes only the prefix provider, the audit sink and the single-file lookup.
- Web fake realism (a note, not a failure): `FileExplorerQuarantineTests.ServeState` ignores `folderPath` and the fake add/remove take only the leaf name from the path. It does not model the prefix. That is acceptable because the Web contract is root-relative by design and the prefix semantics are covered end-to-end in the Api tests. The Web tests therefore prove only that the Web sends the path it received, not that the server resolves it.

## 10. Reviewer Notes

1. **Focus restoration (§2.7).** After a confirm or an action, rows are re-keyed (`checkResetVersion++`), and `FocusCheckAsync` runs right after `StateHasChanged`. `checkRefs` may still hold the pre-render reference, so focus could be lost. The code catches `JSException` and `InvalidOperationException`, so nothing breaks. It is untested and unverified in a real browser. Suggest a manual accessibility pass or a small focus test.
2. **Dialog keyboard handling.** The dialog has `role="dialog"` and `aria-modal`, but I found no Escape handling or focus trap. It matches the existing `cachet-confirm` pattern, so it is not a regression.
3. **Web fake does not model the prefix.** See §3. This is acceptable because Api tests cover it. A comment in `FileExplorerQuarantineTests` noting that the paths are root-relative by contract would help future maintainers.
4. **Failed state re-read after a successful action.** The success message is overwritten by the generic error, and the column is hidden until the next navigation. It is safe (it never shows unknown state as unchecked) but may confuse users. Acceptable.
5. **Spec housekeeping.** SC-6 says "list double-click" while the explorer navigates on single click. §16 checkboxes are unticked and the Reviewer sign-off is blank. The spec status is `review` and should move on after sign-off. CAS-053 is still `in-progress` even though its code, unit tests and the integration test exist.
6. **Unattributed state.** I could not diff for CAS-052 changes to `QuarantineQueueModal.razor` (no git). Nothing in the CAS-051 files references it.
7. **Skipped test.** One skipped test in the Web filter (`Test_SC1_TriggersOnBothPagesOpenModalInCorrectMode`) is unrelated to CAS-051.
