## 10. Reviewer Notes

1. **Unhandled deserialization failure (robustness, minor).** `AuditLogModal.razor:287` calls `ReadFromJsonAsync` outside the try/catch. A 2xx response with a non-JSON or malformed body (for example an HTML page from a misrouted proxy) would throw `JsonException` or `NotSupportedException` out of the event handler. That surfaces as a Blazor circuit error, and `isLoading` stays `true`. §6 does not list this case, and the sibling modals have the same pattern (`QuarantineQueueModal.razor:193`, `TaskManagerModal.razor:206`), so this is consistent with local convention rather than a spec defect. Consider a cross-modal hardening change spec.
2. **Telemetry content is not asserted.** `AuditLogModalTests` registers `CapturingLoggerProvider` (`:28`, `:34`) but never asserts on it. Code inspection confirms §11 compliance (no row contents are logged), but a regression test proving the log contains no `user`, `filePath` or `resultDetail` would give auditable evidence for the data-minimisation claim.
3. **`HttpResponseMessage` is not disposed** (`:268-287`). This is negligible for small JSON bodies and matches the sibling modals.
4. **§4 wording is stale:** "Pre-/Post-Action Report buttons stay CAS-025's disabled placeholders". CAS-032 has since enabled them. Consider a one-line spec note so future reviewers do not flag it.
5. **Graph gap:** graphify does not index `.razor` files, so Blazor components are invisible to `query`, `explain` and `path`. Future Web-spec §17 sections will keep needing manual fallback until the extractor covers Razor.
6. **Carried forward from §17:** filtering by "Quarantine" does not show quarantine *additions*, because they are written under "Keyword Search". This is correct per the stored data. Testers should not log it as a defect.
