  project), so the actual runtime toggle-on-input behavior is proven by code inspection of login.js

  otherwise a JS unit test") and the chosen fallback is reasonable for a 4-user internal tool;
  flagging only for awareness, not as a gap.

  cookie-middleware challenge path, not Routes.razor line 7 component-level NotAuthorized
  fragment specifically (which only fires on a mid-circuit re-authorization failure). That narrower
  branch is honestly disclosed as unverified by any test in the suite. Given Routes.razor
  measured 50% coverage (Implementation Log) is consistent with this gap, and the practical risk is
  low (the middleware-level gate already covers the dominant real-world case of an expired or
  invalidated cookie on ordinary navigation), this is accepted as a documented, non-blocking
  coverage gap rather than a defect.
- The repository not being under git version control limited scope-purity verification to
  content/grep-based methods rather than a diff against a base commit (see Section 5 caveat). No
  contradicting evidence of a scope violation was found by these methods.
