### Prior finding D-1 trace (Web to Api path prefix), verified in code
- Web sends root-relative paths only. Folder rows use `folder.Path` from the browse response (`FileExplorer.razor:190`, `:965`). State uses `listing.Folder` (`:773`). `FileBrowseService.cs:104,134` builds both as `folderPrefix + name` / `folder`, without the B2 prefix (the prefix is applied only to the SP call at `:72`, `:80`).
- Api `QuarantineBrowseService.ResolveFullPathAsync` (`:241-265`) applies the bucket prefix via `B2KeyPath.Combine` for source `B2`, with a null prefix returning `MappingMissing` before any repository or audit call (fail closed) and over-length returning 422.
- It is used on all three routes: add (`:92`), remove (`:157`), state (`:208`). Audit rows for folder scope carry the full key path (`:111`, `:176`).
- The state SP (`dbo.quarantine_entry_browse_state_lst.sql:37-54,67-77`) matches `relative_path` on `fullPath + '/'` and returns leaf `folder_name`, which the Web keys on `folder.Name` (`:178`, `:792`, case-insensitive dictionary). The Web and Api agree.
- File-scope writes use the global `file_index_id`, so no prefix is involved.

## 10. Reviewer Notes

I looked for blocking defects specifically in prefix handling, pessimistic update, audit ordering, and Read Only gating and found none. Real but minor items:

1. **Stale state after a rejected action (new).** `AfterQuarantineActionAsync` (`FileExplorer.razor:893-905`) re-reads state only on success. If another user already quarantined the file (Api 409) or removed the entry (404), the Web shows the generic error and the checkbox reverts to the old model state, which is now wrong until the next navigation. Safe (never claims success) but misleading. Suggest re-reading state on `Rejected` as well. Not required by the spec.
2. **Dialog keyboard handling.** `role="dialog"`/`aria-modal` present; no Escape handling or focus trap. Matches the existing `cachet-confirm` pattern, so not a regression.
3. **Focus restoration unverified in a real browser.** `FocusCheckAsync` runs right after the rows are re-keyed (`checkResetVersion++`), so `checkRefs` may reference the pre-render element. Exceptions are swallowed. Recommend a manual accessibility pass.
4. **Api write-route input hygiene (defense in depth).** `QuarantineBrowseService.IsValid` (`:268-283`) rejects leading and trailing `/` but not `..`, `//`, `\` or control characters, unlike `FileBrowseService.IsWellFormedFolder`. Values reach the SPs as parameters with LIKE-escaping and the bucket prefix is always prepended, so I found no exploitable path; a malformed path yields 404. Optional follow-up for the CAS-050/053 owner.
5. **Silent absence when the bucket is not configured.** If `B2:BucketName` is empty in Web, `QuarantineEnabled` is false and Full Access users see no checkboxes and no message. Matches Keyword Search's existing precedent.
6. **After a successful action, a failed state re-read overwrites the success message** and hides the column until navigation (`:786-803`). Safe and acceptable.
7. **Spec housekeeping.** SC-6 says "double-click" but the explorer uses single click. §16 checkboxes and Reviewer sign-off are blank; frontmatter status is `merged`.
