## 10. Reviewer Notes

1. **Stale class doc comment.** `ODriveSyncCopyMirrorSyncTests.cs:10-13` still says the call is made "never for Update/Purge". It should now say "never for Update". This is documentation only.
2. **Known limitation verified as accurate.**
   - `B2MirrorSyncTaskProcessor` only downloads and replaces files. Its only `File.Delete` removes its own `.cachet-partial` temp file (`B2MirrorSyncTaskProcessor.cs:276-284`), and there is no orphan or local-delete logic.
   - `SyncPurgeTaskProcessor` contains no `File.`/`Directory.`/mirror references; it deletes B2 versions only.
   - So purged files remain in `\\svsws10\B2mirror`, exactly as §2 states.
3. **Copy and Purge finishing together.** Each has its own `ActionPollState` (`copyState`/`purgeState`), so each triggers independently. The second gets 409 and retries every poll interval up to `MirrorSyncMaxAttempts`, then shows the informational toast. This is the intended CAS-060 V2 behaviour; there is no defect.
   - A new Purge submitted while the previous Purge's 409 retry loop is running cancels the old `pollToken`. `Task.Delay` then throws `OperationCanceledException`, which is caught silently (`razor:1421`), and the new Purge triggers its own call.
4. **Partial per-file Purge failures.** The task still ends `Completed`, so Mirror Sync is triggered. This is harmless, because Mirror Sync is idempotent and only downloads.
5. **CAS-060 behaviour preserved.** The Copy prefix is still "Files copied." (`razor:1434`), and all 11 CAS-060 tests pass.
6. **Closing the page before the Purge completes** (and not reopening it) means no Mirror Sync call. This is consistent with §2 ("polling stops early").
