## 9. Findings

- **F1 (Medium, V6) — stale-selection pruning is effectively dead code.** Modal.razor:301-307 runs only when
  `previousLoadedPage == page`; every reachable `LoadAsync` path avoids it (open clears selection; page change
  always changes page; size change and delete clear selection first; clamp retry uses a different page). The
  "absent from reloaded rows on page change" half of V6 is not delivered: select a row on page 1, another
  session deletes it, go to page 2 and back, and the row is still counted. `Test_V6_StaleSelection_Pruned`
  (ModalTests:772) would still pass if lines 301-307 were deleted. Impact bounded (endpoint returns per-file
  `file-not-found`; confirm count may overstate). Fix either: per-page ID snapshot pruned on every fetch plus
  a test that mutates the store between visits; or delete the dead code and amend V6 to "clear-after-delete".
- **F2 (Low–Medium) — failed delete does not reload.** Non-2xx (Modal.razor:420-429), including 404
  `AllFilesNotFound`, shows the banner and clears the selection but leaves stale rows. Pre-existing, but more
  likely with cross-page selection. Cheap fix: `LoadAsync()` on 404.
- **F3 (Low) — actions enabled during page load.** Delete/Clear not disabled while `isLoading`; a click can
  compute `confirmOtherPagesCount` against the previous page's rows (:372).
- **F4 (Low) — Q-C chip styling.** §14 says neutral/muted; code uses the blue informational style
  (Modal.razor:476, KeywordSearch.razor:1432); tests assert that class.
- **F5 (Info) — §16 narrow-breakpoint pager check UNVERIFIABLE** (needs visual check; pager uses `flex-wrap`;
  `KeywordSearch.razor.css` unchanged though listed in §5).
- **F6 (Info) — housekeeping.** Stale comment at KeywordSearch.razor:339-341 ("fixed Source Tab value");
  Implementation Log "Tests ✓" hides the Gate 2 waiver.
