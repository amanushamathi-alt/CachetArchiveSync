## 10. Reviewer Notes

1. Log-hygiene test scope (non-blocking). Both FileContentMatcherTests' corrupt-bytes tests and
   KeywordSearchTaskProcessorTests's log-hygiene assertions verify the formatted message template
   produced by the ILogger call (via NSubstitute's captured formatter delegate), not what a real
   logging sink (Console/File/Serilog) would additionally render for the attached Exception object's
   own Message/stack trace. Some third-party binary-format parsers (NPOI, PdfOxide, b2xtranslator)
   can, in principle, embed a fragment of the file's header bytes in their own exception message
   (e.g. a magic-number mismatch string) when thrown against corrupt/malformed input. This is not a
   CAS-012-introduced pattern - LogWarning(ex, fixedTemplate, ...) is used identically throughout
   the codebase (LoginService.cs:88, Worker.cs:69, SyncCopyTaskProcessor.cs:150, etc.), including in
   a B2-key-material failure path, so it appears to be an accepted, pre-existing convention rather
   than a defect specific to this change. Suggest a follow-up spec (not this one) to either (a)
   confirm the specific extractor libraries in use never embed byte content in exception messages,
   or (b) standardize on logging only the exception's type name for this class of failure rather
   than the full exception object.
2. Stale package-comment (cosmetic). Cachet.ArchiveSync.Api.csproj's comment above the CAS-012
   package block still says "PdfPig (pure-managed PDF text extraction)", but the actual
   PackageReference is PdfOxide - the Implementation Log correctly documents the swap ("PdfOxide-
   based .pdf extractor (swapped in after UglyToad.PdfPig failed nuget restore verification)"), but
   the csproj's own inline comment was not updated to match. Purely cosmetic; does not affect build
   or behavior.
3. Third-party package provenance (informational, no internet/registry access available in this
   sandbox). Two of the three new packages (PdfOxide 0.3.78, GHSoftware.WordDocTextExtractor 1.0.4)
   are lower-maturity/niche compared to NPOI 2.6.2 (a long-established, widely used Apache POI .NET
   port). The Implementation Log and this spec's own test-asset README document the rationale (NPOI's
   HWPF module is genuinely unimplemented for .doc; PdfPig failed a nuget restore verification in the
   implementer's environment) and the .doc fixture's provenance/license (BSD-3-Clause, from the same
   b2xtranslator project GHSoftware.WordDocTextExtractor wraps). This is a reasonable engineering
   trade-off given the stated constraints, but for a regulated application a dependency/SBOM review
   of these two packages (signing, maintenance cadence, known CVEs) before production deployment is
   a sensible follow-up, since this reviewer has no live registry access to perform that check.
4. Stale class-level doc comment (pre-existing, not introduced by CAS-012). FileIndexRepository.cs's
   XML doc still says dbo.file_index_search and dbo.file_index_soft_delete_upd "have not yet been
   authored by db-author (BLOCKED...)" - both procedures demonstrably exist and are called
   successfully by this same file. This predates CAS-012 and was not touched by it; noted only
   because a reviewer reading this file cold would be misled by it.
5. coverage.py fix (see section 5) - disclosed, reasonable, out of the declared file lists' scope
   but not a behavioral scope violation.

None of the above block merge.
