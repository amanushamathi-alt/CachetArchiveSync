## 10. Reviewer Notes

1. Stale "BLOCKED" XML-doc comments (non-blocking, cosmetic). TaskQueueRepository.cs,
   FileIndexRepository.cs, ITaskQueueRepository.GetAsync, and IFileIndexRepository's class doc
   still read as if dbo.task_queue_get, dbo.file_index_search, and dbo.file_index_soft_delete_upd
   "have not yet been authored by db-author (BLOCKED...)" and "will fail at runtime against a real
   database until db-author adds these procedures." This was evidently true at some intermediate
   point during implementation but is no longer accurate - the addendum migration
   (20260922_173000...sql) adds all three procedures with matching signatures, and both integration
   and unit tests exercise the resulting code paths successfully. Recommend a follow-up doc-only
   pass to remove the "BLOCKED" language so a future reader does not mistakenly believe these
   repositories are non-functional against a real database.
2. GET /search/{taskId}/results intentionally has no explicit Unauthorized() branch. Unlike
   POST /search and POST /search/results/quarantine, SearchController.GetResults does not call
   GetUserId()/Unauthorized() - this is correct per Section 6's "not restricted to the submitting
   user" ownership-scope decision (no user-id needed for this read), and the framework's
   [Authorize(Policy = "CachetAuthenticated")] attribute still enforces the 401 for an
   unauthenticated caller before the action body runs. Confirmed by
   Test_GetResults_NoSession_Returns401 passing.
3. QuarantineService's actor-identity stopgap is self-disclosed in code (QuarantineService.cs:66-74)
   - numeric user id used verbatim as the NVARCHAR(50) "quarantined by" actor identity, since no
   username-by-id lookup exists in this codebase yet. This is flagged in the code itself as a
   documented, best-effort choice rather than hidden, consistent with the project's stated
   precedent (CAS-002's LoginResponse.DisplayName). Recommend a human product/security sign-off on
   whether a numeric id is acceptable as the audit-adjacent "quarantined by" value long-term, or
   whether it should later resolve to a username.
4. Three DB-level integration tests (SC-9/SC-10 DB round-trip, SC-12 concurrency) remain
   Skip-marked pending a live SQL Server instance - disclosed in the Implementation Log's Gates
   line and in each test class's own doc comment, matching the CAS-005 precedent. Recommend these
   be run manually against a real SQL Server instance before production go-live, as their own Skip
   reason text already states.
